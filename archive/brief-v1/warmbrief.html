Escalation · Supervisor handoff

Warm Brief

When the caller escalates, inject a structured briefing via addInfo — stay on call instead of fragile transfer().

FOLD IN → Glass Box Vertical: BPO / Insurance FNOL

What it is

On escalation, the Expert compiles collected Fields into a supervisor briefing object and calls addInfo("escalation_brief", {...}) so the agent continues the conversation with full context — simulating a warm handoff without dialing a human in the demo room. The console shows the briefing card the moment onEscalate fires.

Why it matches real Guava

  • onEscalate — fires when caller asks for human OR agent initiates; event.requestedBy is 'human' | 'agent' (on_escalate).
  • addInfo(label, info) — "persists for the duration of the call and surfaces naturally when relevant" (add_info).
  • transfer(destination) — documented escalation response, but impractical in-room (no live supervisor phone) (on_escalate example).
  • Help desk routing — onAction + transfer pattern in help-desk.ts — Warm Brief replaces transfer with context injection for demo.
  • BPO vertical — "Full QA and audit trails" on goguava.ai — briefing card is QA-visible context.
  • onActionRequest caveat — if you implement it, you must handle human escalation requests yourself; otherwise onEscalate handles caller requests (docs).

Architecture

Expert

agent.onEscalate(async (call, event) => {
  const brief = {
    requestedBy: event.requestedBy,
    policyNumber: await call.getField("policy_number"),
    lossType: await call.getField("loss_type"),
    lossDate: await call.getField("loss_date"),
    summary: "Caller frustrated about adjuster delay.",
  };
  await call.addInfo("escalation_brief", brief);
  // Do NOT transfer in demo room — agent stays on call with new context
});

Console — Escalation panel renders brief from bridge event; show requestedBy badge (human vs agent).

How you win

  • Pragmatic escalation — shows you read on_escalate AND add_info docs
  • Avoids demo-killing failed transfer
  • BPO/insurance buyers care about handoff quality — direct vertical fit

Risks & fallback

  • Agent doesn't verbalize brief — add Say step after addInfo in checklist if needed (Tasks — Say)
  • onActionRequest intercepts escalation — don't implement action routing unless required
  • Fallback: show briefing card in console only; narrate what agent "knows"

What NOT to do

  • Don't transfer("+1...") to your cell on venue Wi-Fi — unreliable
  • Don't build soft-transfer telephony — out of scope for 4 hours
  • Don't implement onActionRequest without handling escalation yourself

Build Night Brief Idea 01 · PICK

Insurance FNOL · Supervisor console

Glass Box

Live FNOL supervisor console for Harbor Mutual — see every field, transcript turn, and escalation as the caller speaks.

PICK Vertical: Insurance FNOL

What it is

A split-screen demo: left side is a Guava WebRTC voice call collecting a first notice of loss; right side is a Next.js supervisor console that lights up checklist fields in real time, shows a live transcript via speech callbacks, redacts sensitive digits in the UI, and surfaces a briefing card when the caller escalates — all without leaving the call.

This is the product surface Guava markets as "One platform. One log. One accountable team" on their homepage, but they ship code-first Experts without a live floor UI.

Why it matches real Guava

  • Insurance FNOL is a named vertical on goguava.ai — "Claims captured. Adjusters working cases, not voicemail."
  • Task + Field checklists drive structured intake per Tasks docs and Field docs — same pattern as restaurant-waitlist.ts, applied to FNOL fields.
  • Speech surveillance — docs explicitly recommend onCallerSpeech / onAgentSpeech for "call surveillance or real-time transcription logging" (on_caller_speech, on_agent_speech).
  • Escalation + context — onEscalate fires on human or agent request (on_escalate); addInfo() injects supervisor briefing that persists for the call (add_info).
  • WebRTC in-room — listenWebrtc() + embed widget (WebRTC Widget, Agent entrypoints).
  • Post-call audit — Conversations API for transcript/recording after hangup (Conversations API) — show the "One Log" card populated from GET /v1/conversations/{call_id}/transcript.

Architecture

Node Expert (expert/)

  • guava create harbor-fnol → TypeScript Expert
  • agent.onCallStart → setTask("fnol", checklist=[...])
  • agent.onTaskComplete → log fields, optional hangup()
  • agent.onCallerSpeech / onAgentSpeech → push to SSE/WebSocket bridge
  • agent.onEscalate → addInfo("supervisor_brief", {...}) — no transfer() in demo room
  • agent.listenWebrtc(code) — verify TS method name after guava create

Next.js console (console/)

  • Field checklist UI — state from Expert bridge events
  • Live transcript pane — caller/agent utterances
  • Redaction display for sensitive fields (mask last-4 in UI even before post-call API)
  • Escalation banner + briefing card when onEscalate fires
  • Guava widget script tag for WebRTC call surface
  • Post-demo: fetch transcript via Conversations API (Bearer API key, server-side route)

Bridge: lightweight WebSocket or Server-Sent Events from Expert stdout — no undocumented Guava REST for live events. TS SDK handlers: verify camelCase (onCallerSpeech) in generated project.

Demo script (~75s)

"Harbor Mutual gets FNOL spikes after storms. Guava's Expert collects the claim — but adjusters today have no live floor view. Glass Box is that missing supervisor console."

[Start WebRTC call] "I'm reporting water damage from yesterday…" — watch fields turn green as policy number, date, and loss type complete. Transcript streams on the right.

"When I say 'connect me to a supervisor,' onEscalate fires — we inject a briefing via addInfo so Grace stays on the call with context, no broken transfer in this room."

[Hang up] "Post-call, Conversations API gives us the same call in One Log — transcript with sensitive fields redacted per Guava's Field docs. This is the regulated runtime they sell, plus the UI they don't ship."

How you win

  • Fills their marketing gap — "one log" + "supervisor agent" on homepage, but no live dashboard in SDK examples.
  • Right vertical — insurance FNOL is Guava's bread-and-butter, not another waitlist clone.
  • Uses rare callbacks correctly — speech handlers for surveillance per docs, not prompt hacking.
  • Compliance story — sensitive digit_sequence, redaction visible live + in stored transcript.
  • Code-first credibility — Expert in Node, console in Next — matches architecture (architecture overview).

Risks & fallback ladder

  1. agent.chat() — terminal text session, pipe events to console
  2. agent.callLocal() — laptop mic if WebRTC flaky
  3. debug-webrtc — isolate widget vs Expert
  4. agent.roleplay("Storm caller reporting FNOL…") — automated demo if audio dies (agent testing)
  5. Mock bridge — replay canned JSON events into console UI

What NOT to do

  • Don't run Expert inside Next.js API routes — SDK is Node Expert process, not edge
  • Don't use outbound/SMS — needs approval; WebRTC only tonight
  • Don't invent live webhooks — Conversations API is post-call only
  • Don't clone restaurant-waitlist verbatim — FNOL + supervisor UI is the differentiator
  • Don't transfer() to a real phone in the demo room — use addInfo stay-on-call
  • Don't wrap Wing Mic or build AdvanceIQ/Power BI chat

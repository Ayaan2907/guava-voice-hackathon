PCI compliance theater · Sensitive fields

Redact Last-4

Show Guava's redaction pipeline live — collect last-four via digit_sequence + sensitive, never real PAN.

FOLD IN → Glass Box Vertical: Banking / PCI

What it is

A focused compliance demo within the supervisor console: when the FNOL or verification flow collects account last-four or a test card number, the console shows the raw value briefly then masks it — mirroring what Guava does to transcripts and recordings. Side-by-side: live UI mask vs post-call transcript from Conversations API proving redaction persisted.

Why it matches real Guava

  • Sensitive fields — sensitive=True redacts from stored transcripts and silences audio in recordings (Field docs — Sensitive Fields).
  • digit_sequence — for account/ID/card numbers; docs show SSN last-four example with digit_sequence + sensitive.
  • PCI path — full card via digit_sequence + sensitive; CVV via dedicated cvv field type with session-wide log/diagnostic suppression — same doc page.
  • Banking vertical — KYC/identity verification on goguava.ai homepage.
  • Certifications — PCI DSS Level 1 marketed on FAQ and all plans.

Architecture

Expert — add to Glass Box checklist:

guava.Field({
  key: "account_last_four",
  question: "What are the last four digits of the account on file?",
  fieldType: "digit_sequence",
  sensitive: true,
})

Console — on onTaskComplete event for that field, display ••••1234 in supervisor pane. After call, fetch GET /v1/conversations/{call_id}/transcript — show redacted turn text.

Verify TS property names (fieldType, sensitive) in generated SDK. Never collect real PAN — use fictional "4111…" spoken as test only, or skip full card entirely.

"For regulated calls, Guava redacts sensitive digit_sequence fields from transcripts and recordings. Watch the supervisor pane mask last-four the moment it's captured — then after hangup, the Conversations API transcript shows the same redaction. We're using test digits only — never real card data in a hackathon room."

How you win

  • Makes abstract compliance docs visible — judges see redaction, not just hear "we're PCI."
  • Differentiates from waitlist demo — touches banking/PCI story Guava sells.
  • Zero extra Expert — one field, one UI panel, high signal.

Risks & fallback

  • If live redaction hard to verify — screenshot pre/post transcript from dashboard Conversations view
  • If cvv field overkill — stick to digit_sequence + sensitive per docs
  • Fallback: static before/after transcript JSON in console mock

What NOT to do

  • Never collect real primary account numbers or CVV
  • Don't build a standalone PCI app — fold into Glass Box
  • Don't claim HITRUST/PCI audit — cite Guava's certifications, show field-level behavior
  • Don't use cvv field unless demonstrating session-wide suppression — adds scope

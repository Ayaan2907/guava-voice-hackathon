Roleplay Studio

Visual wrapper around agent.roleplay() and session.evaluate() — ship test rubrics, not live voice wow.

BENCH Vertical: DX / QA

What it is

A Next.js page that triggers automated caller roleplays against your Expert, displays the transcript, and runs pass/fail rubrics via session.evaluate(). Think "pytest UI" for voice agents — valuable to Guava eng, less theatrical for a 90-second live demo.

Why it matches real Guava

  • agent.roleplay(prompt) — LLM improvises as caller; handlers fire like real calls (Automated Testing).
  • session.evaluate(pass_criteria, fail_criteria) — rubric assessment on returned TestSession.
  • agent.test() — precise utterance injection alternative for scripted demos.
  • MockCall — unit-test individual handlers (onActionRequest, etc.).
  • agent.patch() — override handlers for scenario testing without modifying source.
  • Reference implementation: help-desk.ts + test patterns in SDK repo.

Architecture

Node Expert — expose HTTP endpoint (your own, not Guava) that runs:

const session = await agent.roleplay(
  "You are an angry caller reporting hail damage to your roof."
);
session.evaluate({
  passCriteria: ["Agent collected loss date and policy number."],
  failCriteria: ["Agent promised a specific payout amount."],
});
return { transcript: session.getTranscript(), ... };

Next.js — form for roleplay prompt + rubric lines → calls your endpoint → renders transcript + pass/fail badges.

No Guava REST for roleplay — must invoke SDK from Node Expert process.

Demo script (~60s)

"Guava agents are code-first — testing should be too. Roleplay Studio runs agent.roleplay() with an LLM caller, then session.evaluate() against your rubric."

[Click Run] "Angry hail-damage caller" — transcript scrolls, fields complete, rubric shows pass on 'collected policy number', fail if agent hallucinates payout.

"This is how you'd CI voice agents — but tonight I'd rather show you live WebRTC with Glass Box."

How you win (if you pick this)

  • Speaks directly to Guava eng / developer audience
  • Proves you read agent-testing docs deeply
  • Reliable demo — no mic, no Wi-Fi audio issues

Why BENCH: Judges want to hear voice AI tonight. Roleplay is silent text — strong backup, weak headline.

Risks & fallback

  • Roleplay latency — pre-run sessions, show cached results if live run slow
  • Evaluate flakiness — keep rubrics simple and observable
  • Fallback: terminal output of guava test / pytest if UI breaks

What NOT to do

  • Don't ship this as primary if Glass Box is viable — voice wow wins hackathons
  • Don't invent Guava test APIs — only documented roleplay, test, evaluate
  • Don't skip live voice entirely — judges expect WebRTC
